# Quick Revision

Use this file for active recall before interviews. Keep each completed-topic card short enough to review in about one minute. Cards are added only after an evaluated session so they contain corrected conclusions rather than assumed knowledge.

## Universal LLD Checklist

1. Clarify actors, core use cases, constraints, and what is out of scope.
2. State the invariants before choosing classes or patterns.
3. Define the smallest useful API and walk through the critical path.
4. Add extensibility only for a stated variation.
5. Identify shared mutable state and its synchronization boundary.
6. Cover invalid input, duplicate operations, partial failure, and cleanup.
7. Verify with normal, boundary, invalid, and concurrent cases.

## Universal HLD Checklist

1. Clarify functional requirements, scale, latency, consistency, and availability.
2. Estimate traffic and storage only where the numbers affect a decision.
3. Define APIs and the data model before drawing components.
4. Walk through the primary read and write paths.
5. Find the first bottleneck, failure boundary, and scaling mechanism.
6. Discuss retries, idempotency, observability, security, and evolution selectively.
